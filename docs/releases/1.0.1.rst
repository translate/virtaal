Virtaal 1.0.1
*************

.. This page is the human-readable summary of a bug-fix release: what a
   user of 1.0.0 will notice, not a line-by-line changelog. Keep it
   short and readable by someone who has never opened an issue tracker.
   Hand-maintained alongside docs/releases/1.0.1-github-notes.md (the
   GitHub release body) - update both together.

Virtaal 1.0.1 fixes problems found in 1.0.0, many of them by our own
testing and a full review of 1.0.0's code. It adds no new features and
no new text to translate, so every translation that shipped with 1.0.0
is still complete.

The biggest change: **the Windows and macOS packages now underline
misspelled words as you type**, as Linux always has. This was 1.0.0's
main known limitation. It works on both Apple Silicon and Intel Macs,
and a spelling dictionary Virtaal downloads for your language is used
straight away, without restarting Virtaal.

Getting it
==========
Windows installer, macOS ``.dmg`` (Intel and Apple Silicon, macOS 15
Sequoia or later), and a Linux Flatpak (x86_64 and aarch64) - see
:ref:`Installation <index#installation>`.

Each release also has a Linux AppImage (x86_64 and aarch64), as a beta:
it isn't a supported way to install Virtaal yet. It runs from wherever
you save it, adds itself to your applications menu, and checks spelling
with the dictionaries installed on your system.

.. note::
   The macOS builds are signed and notarized by Apple, and the Windows
   installer is signed by Translate House Ltd. Windows may still show a
   blue "Windows protected your PC" screen for a while, until
   SmartScreen recognises the new certificate: click **More info**, then
   **Run anyway**.

Saving and file formats
=======================
- Saving is safer: Virtaal now writes a new file and then replaces the
  old one, so a full disk or an error while saving no longer leaves a
  cut-short or empty translation file. Downloaded glossaries and word
  lists are saved the same way.
- On Linux and macOS, if Virtaal is closed from outside with unsaved
  changes (closing the terminal it was started from, or logging out or
  shutting down on Linux), it keeps a copy of your changes instead of
  losing them, and Ctrl+C in that terminal asks whether to save them.
  See
  :ref:`Recovering Unsaved Changes <tips#recovering_unsaved_changes>`.
- TMX and XLIFF: a translation that starts with an inline tag no longer
  keeps its old text when you change it; files declared as UTF-16 no
  longer save as files that can't be reopened; an XLIFF file with a
  processing instruction, and a TMX file declared as US-ASCII that holds
  accented letters, can be saved; and Search & Replace no longer removes
  the inline tags from an XLIFF translation.
- XLIFF (all packages but the AppImage): an XLIFF or SDLXLIFF unit you
  only looked at no longer loses the space between its sentences when
  the file is saved, and text after an XML comment in a translation is
  no longer dropped. XLIFF, TMX and QPH files keep their UTF-8 byte
  order mark, and an XML file in an encoding Virtaal can't write is
  refused when you open it instead of being saved empty.
- XLIFF units in the states needs-l10n, needs-review-l10n, final or new
  are counted in the statistics and added to translation memory after
  you edit them, and undo works on them.
- Qt Linguist: translating a message with length variants no longer
  deletes the variants, accented and non-Latin source text in a .qm file
  is no longer garbled, and a .ts plural form no longer shows the source
  of a file you had open before.
- Project bundles (.zip): saving a bundle works, a read-only bundle can
  be opened, and Save As writes the copy you name instead of overwriting
  the bundle you opened.
- A unit you translate is now always marked translated, however quickly
  you move on or save. Leaving a unit straight after typing could mark
  it as needing review.
- File > Update from Template is offered only for PO files, where it
  works. On other files it failed and left the editor blank. Its notice
  with the before and after counts now goes away when you open another
  file.
- A file whose name has characters such as % or spaces opens from a file
  manager or launcher.
- Saving straight after Virtaal opens, before it has finished starting,
  no longer shows "Could not save" for a file that was saved.

Editing, search and navigation
==============================
- Several things that could freeze Virtaal: moving to a unit with a very
  long word (a web address, a code) with no spaces, pasting a very long
  text with spell checking on, a regular expression search that would
  run for minutes (it now stops after two seconds and finds nothing),
  and searching for a space while the current unit holds a very long
  text. Moving onto or off a unit with thousands of lines is faster.
- Choosing Hungarian for spell checking no longer stops Virtaal
  responding.
- A source text with a NUL character is shown in full instead of being
  cut short at it.
- Plural units: clicking into another plural form now sends a
  translation memory suggestion to that form, not the first one; Enter
  in the last form of the last unit stays there instead of jumping back
  to the first form; and a plural unit with some forms filled gets
  suggestions for the empty ones.
- Undo: Replace All where every match is in the source text no longer
  greys out Undo and loses Redo, and Ctrl+Z straight after typing a
  search runs the search instead of giving an error.
- Autocomplete now offers whole words in Indic scripts and Persian
  instead of breaking them at vowel signs and the zero-width non-joiner.
- A very long translation memory suggestion shows only its first lines,
  so it fits in the window and no longer holds up typing and
  autocorrect.
- Closing the window with a dialog open and choosing Cancel at the save
  prompt no longer brings the prompt straight back, again and again.
- Dialogs open with their own title, not the title of the last dialog
  shown.
- Text you type into Preferences and other dialogs (your name, e-mail
  and team, a language name or plural rule, a web look-up) comes back
  exactly as typed after a restart, including spaces at the ends, line
  breaks, and lines starting with ; or #.
- A font setting with no size no longer shows the text too small to
  read, and one with no font name no longer gives an error.
- Virtaal no longer stays running without a window when part of it fails
  while quitting.
- Closing the update notice now stops Virtaal offering that version again; a
  newer release still shows it.
- The update notice still finds the download when a later release adds the
  version to its file names.

Translation memory, terminology and downloads
=============================================
- "This file" suggestions now come only from the file you have open, not
  from files you opened earlier, possibly in another language.
- Pontoon terminology: Portuguese (pt) no longer uses or overwrites
  Brazilian Portuguese's terms, and the terms you already have stay when
  an update fails or a network login page answers instead of Pontoon.
- One glossary that can't be read no longer stops all your other
  glossaries from loading, and adding a term to a glossary that can't be
  written shows an error you can act on instead of the crash dialog and
  a lost term.
- Without a network connection, dictionary and other downloads now
  report that they failed instead of waiting until you restart Virtaal.
  A bad reply or a disk error during a download no longer shows the
  crash dialog.
- A translation memory server reply Virtaal can't read is skipped
  instead of showing the crash dialog.
- Moses machine translation works for text with accented or non-Latin
  letters, and reports server errors properly.
- Serbian (Latin), sr@latin, stays Serbian (Latin) instead of becoming
  Serbian in Cyrillic script.
- A crash report's link is kept short enough for GitHub to accept it.

Privacy and security
====================
- A failed Google Translate request no longer writes your API key into
  the log, and a web address's password is hidden in the log.
- tm.ini, which holds your machine translation API keys, is now readable
  only by you, also when an older Virtaal created it.
- A language code in a file you receive can no longer make a web look-up
  open another site, or make a download save outside Virtaal's own
  folders.

Windows
=======
- Adding a glossary uses the Windows file chooser, like File > Open.
- The first file you open after an upgrade no longer fails to open while
  another copy of Virtaal is running.
- The installer's Asturian translation no longer identifies itself as US
  English, and the installer leaves out 2 MB of build files Virtaal
  never uses.

macOS
=====
- While a dialog such as Preferences is open, the main window's menu
  items are greyed out, and clicking the main window no longer takes the
  focus from the dialog.
- The View menu no longer has "Show Tab Bar" and "Show All Tabs".
- Menus in languages that write the access key in brackets, such as
  Korean, no longer show "(F)" after each name.

Linux
=====
- Help > About in the Flatpak shows the build's commit, as the other
  packages do, and the Flatpak is tens of MB smaller.
- Fewer errors in the terminal: no spelling traceback on every start of
  the Flatpak, and no "Error loading theme icon" messages from the
  AppImage on systems without the full Adwaita icon theme.
- Wordfast translation memories saved on Windows (UTF-16) are recognised
  as Wordfast files by the file manager.

For packagers and developers
============================
- translate-toolkit 3.20.6 on Python 3.11 and newer, as in the Windows,
  macOS and Flatpak packages. Python 3.10, which the AppImage is built
  with, stays on translate-toolkit 3.17.5, the last release for it.
- The packages bundle only the translations po/LINGUAS and
  po/LINGUAS-lite list, and the Windows installer only the GIO modules
  Virtaal loads.
- The macOS CFBundleVersion and the Windows file version are now plain
  numbers that increase from a release candidate to its release.
- Several CI and Windows build-script checks that could never fail now
  do, and the Windows test scripts no longer touch a tester's own
  Virtaal settings or stop other running copies.

Known limitations
=================
- Moving onto a unit with thousands of lines still takes a second or
  two.
- XLIFF 2.0 files can't be opened yet.
- In SDLXLIFF files, a translation you type is saved outside Trados's
  segment markers, so Trados may not see it.
- TMX 1.1 and 1.2 files open with empty source text.
- The AppImage is built with an older translate-toolkit, so it doesn't
  have the XLIFF fixes listed above for the other packages: an XLIFF or
  SDLXLIFF unit you only looked at can still lose the space between its
  sentences when the file is saved.
